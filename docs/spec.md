# The Strand language specification

Status: **draft text** (M5 wave 1, S-docs). The section list, the
construct index (section 3) and the compatibility policy (section 14)
are fixed. The text below is complete for every section but is not yet
frozen: it is frozen by the last commit of M5's wave 3 (m5-plan,
"Language spec frozen"). A point marked **(unverified)** is one no
test or decision was found to pin down; the freeze review settles each
one.

## 1. Scope and status

- This file says what a `.strand` program **means**. `docs/grammar.md`
  says how it is **written**: every production, the lexical rules, line
  termination and error recovery. Together the two are the frozen
  language (decisions.md m5-owner, Q5).
- spec.md is self-contained. Its text is copied from design.md and
  adapted, never linked to it, so a later edit to design.md's rationale
  cannot change frozen behaviour. Where design.md is silent, the rules
  come from architecture.md and decisions.md and are restated here.
- spec.md adds no syntax. Every construct it names is a production of
  grammar.md (index in section 3).
- Builtin elements, props, service fields, actions and functions are
  not listed here; they are the builtin and service schemas, published
  as `docs/reference/` (generated by `strand-dev reference`). This file
  fixes the rules every schema entry obeys.
- Numbers given as targets (latencies, memory) are not part of the
  language. Numbers that change what a program does (the 15 ms
  coalesce, the 250 ms overlay delay, the 250 ms settings write delay,
  30 writes per second, the 30 s monitor retention, the 4 px query
  hysteresis, the 5 s service stop) are.

## 2. Conformance and terms

- **must** and **never** are requirements on the implementation;
  **may** is a permission.
- A **load error** stops a program, or the changed set of files in a
  reload, from being committed. `strand check` reports it and exits with
  an error; a running shell keeps its last good tree (section 10.5).
- A **warning** is reported, and the program is committed. A **lint** is
  a warning about style.
- A **runtime fault** is an error while the program runs (section 12).
  Evaluation errors are values, never crashes.
- Every diagnostic carries its file, line and column, a caret under the
  span, a label, and a fix where one exists (a did-you-mean, the missing
  word). One mistake gives one diagnostic. Diagnostic codes
  (`syntax::…`, `check::…`) and message wording are named for reference
  and are **not** part of the frozen surface.
- A program is **accepted** when `strand check` reports no load error.

## 4. Programs and files

### 4.1 The module set

- A **config** is a directory: `$XDG_CONFIG_HOME/strand` by default, or
  the directory given to `strand run` or `strand check`.
- Every `.strand` file at most three directories below the config
  directory is one **module** of one program. Files and directories
  whose names start with `.` are skipped. Symbolic links are followed,
  and each file is one module however many paths reach it (it is claimed
  at its shallowest path). `strand check` warns about deeper directories
  that hold `.strand` files, since they are not loaded.
- There are no imports and no entry file. Every module is loaded.
- Elements and props at the top level of a file are a load error: they
  must be inside a surface or a component.

### 4.2 Names across files

- **Global names** are shared by every module: components, surfaces,
  enums, types, `fn`s, token sets and services. Declaring one twice, in
  one file or two, is a load error naming both places.
- **File names.** A top-level `state` or `let` belongs to its file.
  Another file reads it as `file.name`, and only if it is declared
  `export`; a name that is another file's private declaration is a load
  error that names it and the `export` to add. A file whose exports are
  read must have a name that is an identifier (`my-bar.strand` is a load
  error once it exports), and a file named like a service cannot export
  (the name means the service).
- `export` also makes the value reachable from the command line as
  `file.name` (section 13).
- **Builtins are a prelude.** A declaration may shadow a builtin
  function, value or type within its scope. Shadowing a builtin service,
  or a builtin value such as the time signal `t`, is a warning.
- **Shadowing is loud.** A name in scope that is also a variant of the
  enum a position expects is a load error (the reading would be
  ambiguous); so is a parameter declared again in its body, a file's
  `state` named like a component, and a handler `let` declared twice in
  one block. A prop set twice in one element or one `when` is a load
  error.
- An unknown name is a load error with a did-you-mean: the expected
  enum's variants first, keyframes for `play`, and other files' exports
  as `file.name`.

## 5. Declarations

### 5.1 Surfaces

A surface is something the compositor shows. Its body is a tree
(section 6). Every surface accepts `screens:`, `layer:`, `open:`,
`keyboard:` and `anchor:`, and the events `on show` and `on hide`.
`attach:` and `scrim:` are accepted only on a `panel` (and on a
`popup`); on a `bar`, `osd` or `lock` either one is a load error. On a
`lock`, `screens:`, `layer:`, `anchor:` and `keyboard:` are warnings:
`ext-session-lock` decides all four (every monitor, above everything,
filling the monitor, the keyboard always).

- **`bar Name { … }`** is on every monitor that its `screens:` picks
  (all of them by default). Each monitor gets its own instance, with the
  read-only `screen` (that monitor) in scope, and its own state. A
  monitor plugged in later gets an instance; an unplugged monitor's
  instance is parked with its state for 30 seconds and comes back with
  it if the monitor returns (monitors are matched by make, model and
  description).
- **`panel Name { … }`** is a layer-shell surface for launchers,
  notification stacks and dashboards. **`osd Name { … }`** defaults to
  the focused monitor, the overlay layer, and click-through (an empty
  input region). Both honour `screens: focused`, `layer`, `anchor` and
  `keyboard`.
- **`open:`** says whether a surface is shown. Bound two-way
  (`open: <-> open`), Escape, a click away and focus loss write `false`.
- **`popup { … }`** is an element, not a top-level surface: it is
  anchored to its parent element, shows while its `open` is true, nests
  (a popup may hold popups), and has `on dismiss` (Escape or a click
  away closed it).
- **`keyboard: none | on_demand | exclusive`** sets how the surface
  takes keyboard focus.
- Each surface gets a stable layer-shell namespace, `strand-<Name>`.
- **`lock { … }`** is the lock screen, on `ext-session-lock`. A config
  has at most one `lock`, across its files. A `lock` in which nothing
  calls `auth.submit` is a load error (it has no way out); a `popup` in
  a lock is a warning, since popups never open on a lock surface. The
  lock is exempt from reload (section 10.1) and **fails closed**: if
  anything in it faults, a built-in password field is shown.
  Authentication runs in a separate helper through the PAM service
  `strand`, or `login` with a one-time warning when `/etc/pam.d/strand`
  is missing.

### 5.2 Components and slot

- `component Name(params) { tree }` declares a node kind of your own. It
  is called with the one call shape (section 6.1): `Dot ws`,
  `Toast n { dense: true }`, `Clock`.
- Parameters are `name: Type = default`. A call passes them by position
  (the positional fills the first parameter) or by name in the call's
  block, as props. A parameter with a default may be left out; one
  without a default must be given.
- A parameter's type may be left out where it can be inferred from its
  default or from the values its callers pass; where it cannot, it is a
  load error asking for the type.
- Parameters are read-only inside the component; assigning to one is a
  load error.
- Children written in a call's block render where the component's tree
  has `slot`. Children passed to a component without a `slot` are a load
  error, and so is `slot` outside a component. Each copy of a slotted
  subtree has its own state.
- `component Name(params) tokens { … } { tree }` exposes component
  tokens (section 9.1), read inside as `$Name.token`.
- Components hold state (section 5.3). A cycle of components that always
  mount each other is a load error naming the path.

### 5.3 state, let and export

- **`state x = expr`** declares a writable cell. Its initial value is
  the default expression, evaluated once when the cell is created.
  `state x: T = expr` gives the type; `state xs: [T] key f = []`
  declares a keyed collection (section 6.5).
- **`let x = expr`** declares a derived, read-only value. It is
  recomputed lazily when what it reads changes. Assigning to a `let` is
  a load error.
- **Where state lives.** `state` and `let` may be declared at the top
  level of a file (one cell for the program), in a component or
  surface's tree, or in a list item's tree (one cell per item, per
  instance of the enclosing component or bar). State never lives on a
  leaf element: `text "a" { state s = 0 }` is a load error. `let` may
  also appear in a handler or `fn` body as a local binding.
- An untyped `state i = 0` is an `int` until a fraction is written to
  it; then it is a `float`.
- **`persist`** (`state x = 0 persist`) keeps the value across restarts
  (section 10.3). It is allowed only on a `state` holding plain data:
  not functions, `Async` values, runtime handles or live service items.
- **`export`** (`export state`, `export let`) makes a top-level value
  readable from other files and from the command line as `file.name`
  (section 4.2). It changes nothing else.

### 5.4 Enums and record types

- `enum Kind { volume, brightness }` declares a closed set of variants.
  A variant is written by its bare name wherever the expected type is
  known (`state kind = volume`, `kind == volume`).
- `type Pin { app: AppId; label: text }` declares a record. Records are
  built with call syntax and named arguments: `Pin(app: a, label: "x")`.
  Fields are read with `.`.

### 5.5 Functions

- `fn name(params) -> Type { body }` declares a function. The value of
  the body is its last statement, which must be an expression.
- `fn`s are **pure**: an assignment or an action call in a `fn` body is
  a load error, and so is `await` (section 7.2). A `fn` may call itself;
  runaway recursion is a runtime error value, never a crash.

### 5.6 Custom services and permits

- `service name from dbus system|session "bus.Name" ["/object/path"]
  { fields }` declares a service backed by a D-Bus object. Its fields
  are checked against the object's introspection. A field written
  `name: type rw = Property` is writable (section 8.1); without `rw` it
  is read-only.
- `from file path { fields }` reads a file; `from listen command`
  reads the lines a command prints; `from poll command every T` runs a
  command, or reads a file, at an interval. Their fields are checked
  against the schema you declare.
- Running a command (`listen`, or `poll` of a command) needs
  `permit exec`, at the top level or in the service's block, optionally
  listing the programs allowed; without it the service is a load error.
  A `poll` whose argument is a string naming a path with no whitespace
  (`/…`, `~/…`, `./…`) reads that file each interval and needs no
  permit; to run a program by its path, give the command as a list
  (`["/usr/local/bin/gpu-temp"]`) and permit it. A polled or `from file`
  path that is a program is a warning at check time and a runtime
  failure, never parsed as a document.
- A custom service starts when the program first reads it and stops
  5 s after its last reader leaves, as builtin services do (section
  8.1). Changing its declaration restarts only that service.

## 6. Trees

### 6.1 Elements and the call shape

- Every node is written `kind [positional] { props; children }`, for
  builtin elements and components alike. The positional is one
  expression; it fills the element's positional prop (for `text`, the
  text; for `image` and `icon`, the source) or a component's first
  parameter. Setting a prop both as the positional and in the block is a
  load error.
- A head argument written `name: expr` is the first prop:
  `pages current: page { … }` is `pages { current: page; … }`.
- Which element kinds exist, which props and events each accepts, and
  which children it may hold are schema entries. An unknown element is a
  load error with a did-you-mean that includes the tree keywords
  (`whn` → `when`).
- **Selectors.** In an `svg` element, `#name { props }` applies props
  to the SVG element with that id.

### 6.2 Props and inherited props

- A prop is `name: value`, ended by `;` or a line break. Each prop's
  value is a live expression (section 8.1).
- A prop with several values takes commas: `margin: 8, 8, 0`. Insets
  (`pad`, `margin`) take one to four values read as in CSS: one for all
  sides; two for vertical then horizontal; three for top, horizontal,
  bottom; four for top, right, bottom, left.
- Space-separated groups (`font: "Inter" 13px 500`, a shadow list
  `0 8px 24px $a, 0 1px 2px $b`) are accepted only by font and shadow
  props; elsewhere they are a load error suggesting commas.
- **Inherited props** (`font`, `color`) set on any node apply to every
  descendant that does not set its own.

### 6.3 Conditional style

- `when cond { props }` applies its props while `cond` is true; when it
  turns false, those props return to the values they would otherwise
  have. A `when` block holds props only; a child, handler or other item
  in it is a load error.
- **Source order wins.** When several `when`s, or a `when` and the
  node's own props, set the same prop, the one written last among those
  that apply wins, as in CSS. There is no other precedence.
- `hover`, `pressed`, `focused` and `selected` are booleans of the
  **enclosing node** (the node the `when`, `if` or expression is
  written in). `hover` stays true on a pressed node while it is dragged,
  even when the pointer leaves it.
- To read another node's booleans, give it `id: name` and read
  `name.hover`. An `id:` name is visible across the whole component or
  surface that holds the node. A node's props are never assignable
  through its id (section 8.3).
- `self.width` and `self.height` read the enclosing node's laid-out
  size, for container queries: `when self.width < 300 { … }`. A query
  switches with 4 px of hysteresis, so it cannot flicker, and costs at
  most one extra layout pass per frame.

### 6.4 if, else and match

- `if cond { children } else { children }` mounts the first block's
  children while `cond` is true and the `else` block's otherwise.
  `else if` chains. Unlike `when`, it adds and removes nodes: a removed
  subtree plays its `exit` pose (section 6.6), then unmounts, and its
  handlers are cancelled and its service subscriptions stop.
- `match value { pattern => children, … }` mounts the arm whose pattern
  matches, by the same rules (section 7.3).

### 6.5 for and keys

- `for x in xs { children }` mounts the block once per item of `xs`,
  with `x` in scope. There is no capacity: every item gets its copy.
- Each copy is identified by its item's **key**. Service items and
  keyed collections bring their own (a workspace by its `id`, a
  notification by its `id`). For plain data, write `key e`:
  `for p in pins key p.app { … }`. A `for` over plain data without a
  key is a load error.
- When `xs` changes, copies whose key stays are kept with their state
  and move to their new place (they glide there, section 6.6); copies
  whose key goes play `exit` and unmount; new keys mount and play
  `enter`.
- `state xs: [T] key f = []` declares a keyed collection: each item's
  key is its field `f`. Handlers change it with `push`, `insert`,
  `remove_key`, `move` and `update`. `.filter`, `.map`, `.take` and
  `.sort_by` on a keyed collection or a service list keep keys and update
  incrementally.
- A `list` container lays out and mounts only its visible rows
  (virtualisation is the container's job, not the loop's).

### 6.6 Poses, transitions and keyframes

- **Every visual prop springs.** When a prop's value changes, the node
  animates to it. Movement and size use `$motion.spatial`; colour and
  opacity use `$motion.effects`. A spring retargeted mid-flight keeps
  its velocity.
- **`~` overrides the transition** for one prop:
  `width: 24 ~ $motion.bouncy`, `~ 200ms`, `~ instant`,
  `~ ease(out_back, 300ms)`, `~ bezier(0.05, 0.9, 0.1, 1.05)`. In a
  `when`, the override applies while that `when` wins.
- **What cannot interpolate snaps**: fonts snap, shadow lists are padded
  to equal length and spring, layout lengths (`pad`) snap while paint
  offsets spring. With the desktop's reduced-motion setting on, every
  transition snaps and loops, time signals and effects stop.
- **Paint-only props** (`x`, `y`, `scale`, `rotate`, `opacity`) never
  cause layout. A size spring relays out only the subtree under the
  nearest ancestor whose size does not change.
- **`enter { props }`** is where a node animates in from: on mount it
  starts at those values and springs to its own. **`exit { props }`** is
  where it animates to before it unmounts; without one, `exit` mirrors
  `enter`. Poses apply to surfaces, `if` branches, `for` copies, list
  items and pages. Siblings of a node that is added, removed or moved
  glide to their new places.
- **`keyframes name { 0%, 100% { … }; 50% { … }; duration: T }`**
  declares a timed animation; `play name` in a handler plays it once on
  the enclosing node.

### 6.7 Layout and input

- **Flex layout first.** `row`, `col`, `stack`, `grid`, `scroll`,
  `list`, `split` and `spacer` are containers; flex props and
  `min_*`/`max_*` apply. `place: absolute` takes a node out of the flow,
  placed by `x` and `y`.
- **`split`** has three parts, `start`, `center` and `end`; `center` is
  centred on the split whatever the other two hold. `start`, `center`
  and `end` are only valid in a `split`.
- **Shrinking.** In a full row or column, children give way by `shrink`
  (a flex factor, default 1). An `image` or `icon` sized in absolute
  lengths (`size`, `width` or `height` in px or `ch`, none a percentage)
  defaults to `shrink: 0`. An explicit `shrink:` overrides either
  default.
- **Hit testing** follows the node's rounded shape. `hit: grow(n)`
  enlarges it by `n` for small targets. Shadows enlarge the buffer but
  not the input region.
- **Events go to the innermost node with a handler** for them.
  `propagate()` in a handler passes the event on to the next enclosing
  handler.
- **`nav: id`** on an `input` routes arrow keys to the list with that
  `id`; Return activates the selected row (`on activate`).
- **`tooltip: expr`** shows a tooltip on hover.
- **Drag and drop.** `drag: value` on a source; `on drop(v: T, at: int)`
  on a target. Values from other programs (files, apps, text) arrive as
  typed `Drop` values.
- **`pages`** shows one `page` at a time, with directional transitions;
  hidden pages unmount, so their service subscriptions stop.

## 7. Types and expressions

### 7.1 Types and literals

| Type | Literals and notes |
| --- | --- |
| `int`, `float` | `36`, `0.72`. An `int` widens to `float`. |
| `length` | `4px`, `40%` (of the container), `4ch`; a bare number is px |
| `angle` | `270deg` |
| `duration` | `6s`, `1.2s`, `200ms` |
| `color` | `#7aa2f7`, `#fff`, `#00000080` (3, 4, 6 or 8 hex digits), token paths, colour functions |
| `text` | `"Search apps"`; any UTF-8, escapes `\" \\ \n \t \r \0 \u{…}`; no interpolation |
| `bool` | `true`, `false` |
| `[T]` | `[]`, `["a", "b"]`; lists |
| `T?` | `T` or `null` |
| `Async<T>` | section 8.6 |
| records, enums | sections 5.4 |

- A `T?` value must be unwrapped (`?.`, `??`) before it is used where a
  `T` is expected; using it directly is a load error.
- Using an `Async<T>` where a `T` is expected is a load error (section
  8.6).

**(unverified)** "a bare number is px" for lengths: design.md writes
`height: 36` and `width: 90` for logical pixels; the schema's length
props accept bare numbers. The freeze review confirms the wording.

### 7.2 Operators and calls

- Precedence and associativity are grammar.md's. `==` and `!=` compare
  values; `<`, `<=`, `>`, `>=` compare ordered values (numbers, lengths,
  angles, durations). `&&` and `||` short-circuit. **(unverified)**:
  which mixed-unit comparisons are accepted.
- `a ?. f` is `null` when `a` is `null`, else `a.f`. `a ?? b` is `b`
  when `a` is `null`, or an `Async` that is pending or failed; else `a`'s
  value. Its type is the inner type of `T?` or `Async<T>`.
- `c ? a : b` evaluates only the chosen branch.
- Calls name their arguments by position or by name
  (`month.add(months: -1)`). Builtin functions that take nullable input
  and are marked "null in, null out" (`pct`, `dur`) return `null` for a
  `null` argument; `join(sep, parts…)` joins the parts that are not
  `null`.
- A lambda `x => e` or `(a, b) => { … }` is a value; a lambda is called
  with every argument (lambda parameters have no defaults).
- `await e` is allowed only in a handler (section 8.3); elsewhere it is
  a load error.
- A value that cannot be computed (a stale read, a failed call, a
  runaway recursion) is an **error value**, which propagates through the
  expression and is shown as a runtime fault (section 12); it never
  crashes the shell.

### 7.3 match

- `match value { pattern => result, … }` selects the first arm whose
  pattern matches. A pattern is a variant, a literal or `_`
  (any value).
- A `match` must be exhaustive: an enum match must cover every variant,
  a `bool` match both `true` and `false`, or either may end with `_`;
  any other match must end with `_`. A non-exhaustive
  match is a load error, and so is an arm that can never be reached.

## 8. Reactivity

### 8.1 Three kinds of value

- **`state`** is writable (section 5.3). **`let`s and props** are lazy
  derived values: they are recomputed only when something they read has
  changed, and only when read. **Service fields** are live values,
  writable only where the service marks them `rw`.
- A program is one reactive graph. Each binding records exactly what it
  read; when a written value equals the old one, nothing downstream
  runs. When nothing is written, nothing runs and no frame is drawn.
- A service starts when the program first reads it, is shared by every
  reader, and stops 5 s after its last reader leaves or becomes
  invisible.

### 8.2 One tick, one diff

- Writes made in one tick are batched. Every binding sees a consistent
  set of values (no binding ever sees a mix of old and new values from
  one tick), and the screen receives one change set per tick.
- **State versus events.** A state value is latest-wins: several writes
  in one tick are one change. An event (`on notifications.received(n)`)
  is a lossless queue: every event is delivered, in order.

### 8.3 Handlers

- A **handler** is the body of `on`, `after` or `every`. It is a
  coroutine: it may `await`, and other handlers run while it waits.
- Statements are `let`, `if`, `match`, `for`, `play`, expressions (an
  action call such as `ws.focus()`) and assignments.
- **Assignment** (`=`, `+=`, `-=`, `*=`, `/=`) writes a place: a
  `state`, a field or item of one, an `rw` service field (including one
  on an item of a service's keyed list), or a settings field (written
  field by field). `x op= e` is `x = x op e`. Assigning to a `let`, a
  prop (directly or through an `id`), a parameter or a read-only service
  field is a load error with a fix. Assignment is a statement, never an
  expression.
- A handler's errors are values: a failing action or expression never
  stops other handlers or the shell.
- When a handler's node unmounts, the handler is cancelled at its next
  `await`. A reload that changes a handler's code, or anything it calls,
  restarts it and cancels and reports an in-flight `await`
  (section 10.1).

### 8.4 Events and timers

- `on name { … }` and `on name(params) { … }` run on an event of the
  enclosing node (`click`, `secondary`, `scroll(dy)`, `activate`,
  `drop(v, at)`, a surface's `show`, a popup's `dismiss`), or of a
  service (`on notifications.received(n)`). Which events exist, and
  their parameters, are schema entries.
- **`on change a, b { … }`** runs when any watched value changes. It
  **never** runs for the first value (at boot or mount), for a value a
  reload writes (section 10.3), or when a watched service path switches
  to another object (`audio.sink.volume` when the default sink changes):
  the new object's value becomes the baseline. The watched expressions
  must be reactive (state, settings, services, or `let`s that read
  them).
- **`on change a after T { … }`** debounces: it runs once, `T` after
  the last change.
- **`after T while c { … }`** runs once, after `c` has held for a total
  of `T`; it counts only time during which `c` holds, and schedules
  nothing while `c` is false. **`every T while c { … }`** runs every `T`
  while `c` holds. Without `while`, the condition is always true.
  `every` keeps its phase: host latency does not accumulate. After a
  gap longer than its period it runs once and re-phases, so its next
  run is one period after that one; it never replays missed runs. A
  zero `every` period is an error value naming the timer, reported as a
  runtime fault (section 12), not a silent pause.

### 8.5 Two-way binding

- `prop: <-> target` binds a widget's prop to a writable place: a
  `state`, an `rw` service field, or a settings field. The prop shows
  the target, and when the widget changes the value (a slider dragged, a
  popup dismissed, text typed) it writes the target.
- The prop must be one the schema marks two-way (`value`, `text`,
  `open`, …), and the target must be writable; otherwise it is a load
  error. `<->` takes one expression, a place.
- Writes through `<->` are not counted by the feedback throttle
  (section 8.7).

### 8.6 Async values

- Some calls return `Async<T>` (`apps.search(q)`, `material(image: …)`).
  An `Async` keeps its previous value while a new one loads, and exposes
  `.pending` (a load is in flight) and `.error` (the last load failed).
- `x ?? fallback` covers a pending or failed `Async` (section 7.2).
  Using an `Async<T>` where `T` is expected is a load error, so the
  loading state cannot be forgotten.
- When what an `Async` binding reads changes, the new load supersedes
  the one in flight. A load a handler starts outlives the handler.

### 8.7 Feedback loops

- A **static cycle** (a `let`, token or component that depends on
  itself) is a load error naming the path.
- **Echoes.** A write to a service carries a generation tag; a service
  reporting back the value of a write still pending is ignored.
- **Runaway writers.** More than 30 writes per second to one cell from
  one writer warns (naming the handler) and throttles that writer's
  writes to 30 per second, without losing the last value: in between,
  only the latest value is held, and a compound assignment starts from
  the held value. A writer is a handler, or one run of an input
  handler (below).
- **What is not counted.** Writes from `strand set` and the other
  command-line writes, values a service reports, and writes through
  `<->` are never counted. An input handler (`on click`,
  `on scroll(dy)`, and the other events of a node the user acts on)
  is not counted until its first `await` that suspends; after it, the
  run's writes count against that run alone, not against the handler.
  So `on scroll(dy) { await x; v -= dy * 0.05 }` at 60 Hz, sixty runs
  that each write once, is never throttled, while one run that keeps
  writing more than 30 times a second is. Several runs each below the
  limit are not added up. A handler started by a service event or a timer is
  one writer however many runs it has.
- **Keyed collections.** A throttled writer to a keyed collection
  keeps a held copy of its changes, which lands as one keyed diff when
  its window has room, so items keep their identity; a write that goes
  through in between is merged under it by key, and a change that no
  longer applies is skipped and reported.

### 8.8 Who wins

- `strand set` on a `state` is an ordinary write, the same as a
  handler's.
- For **tokens** and **settings fields** the order is: runtime overlay
  (`strand set`) > file > default. When a save changes a value that a
  runtime overlay shadows, the reload overlay says so:
  `accent: file changed but runtime overlay wins [clear]`. `[clear]`, or
  `strand clear`, removes the overlay (section 13).

## 9. Styling, tokens and theming

### 9.1 Three tiers

| Tier | What it holds | Example |
| --- | --- | --- |
| Palette | A typed schema of colour roles, mapping one to one onto Material 3 system roles | `$surface`, `$fg`, `$accent`, `$on_accent`, `$error`, `$outline` |
| Base tokens | Scales and derived roles, written as expressions over the palette | `$space.2`, `$radius.lg`, `$font.ui`, `$motion.spatial`, `$surface.hi` |
| Component tokens | Knobs a component exposes for overriding | `component Toast(n) tokens { radius: $radius.lg }` exposes `$Toast.radius` |

- Tokens are live values in the reactive graph, never constants fixed at
  load. A token change re-evaluates what reads it; nothing is rebuilt.

### 9.2 Token paths and methods

- `$name.seg.seg` reads a token. Segments are identifiers or integers
  (`$space.2`).
- A segment followed directly by `(` is a **method** on the token before
  it: `alpha`, `mix`, `lighten`, `darken` (`$surface.alpha(0.72)`,
  `$surface.mix($fg, 8%)`). Adding methods later never breaks a token
  name.
- `oklch(from $c, l: l + 0.12)` derives a colour from `$c`'s channels
  (`l`, `c`, `h`, `alpha`).
- An unknown token is a load error with a did-you-mean.

### 9.3 Derived tokens, overrides and lint

- **Derived tokens stay derived.** `fg.muted: $fg.alpha(0.65)`
  re-evaluates whenever `$fg` changes, including every frame of a
  palette animation. Derived tokens form a graph; a cycle is a load
  error. Colour results are gamut-mapped.
- **`tokens name { … }`** declares a token set; **`extends base`**
  starts it from another set. **Redefining a token needs `override`**
  (`override space { 1: 2px }`), a component token included; a
  misspelt `override` or a misspelt token name is an unknown-name error,
  never a new token.
- **`use tokens expr, palette expr`** chooses the active token set and
  palette. Both are expressions, so the choice is live
  (`use tokens prefs.compact ? compact : base, palette scheme`).
- **Lint.** A raw hex colour in a prop, or in a declaration that hands
  it on as a colour (`let`, `state`, a `fn`'s result, a parameter
  default), is a warning (use a token). Defaults in settings files and
  `material(seed:)` arguments are exempt.

### 9.4 Subtree overrides: set

- `set { $token: expr; … }` as a tree item overrides tokens for the
  enclosing node and its descendants. On the right-hand side a token
  names the **inherited** value, so `set { $surface: $surface.alpha(0.5)
  }` is not a cycle. Derived tokens re-derive inside the subtree, and a
  `set` override beats a component token's default.

### 9.5 Palettes, importers and the built-in theme

- A program with no `tokens` or `use` is themed by the **built-in
  theme**: design.md's base tokens (`space`, `radius`, `font`, `motion`,
  `elevation` and the derived roles `surface.hi`, `fg.muted`,
  `fg.faint`, `accent.hover`, `accent.container`, `border`), and the
  palette `material(seed: system.accent ?? #7aa2f7, dark: system.dark,
  contrast: system.contrast)`. A token set that defines only some base
  tokens takes the rest from the built-in theme.
- Palettes come from `material(seed: …)`, `material(image: …)` (an
  `Async`: the image is quantised off the logic thread and cached by
  content), or `import("…")` (Material seed or image, base16/base24,
  Catppuccin, matugen output, W3C design-token JSON). Every importer
  fills the whole palette schema; one table derives any role a source
  lacks.
- `system.dark`, `system.accent` and `system.contrast` follow the
  desktop's portal settings live.
- The last palette is persisted, so boot never shows default colours
  first; the old palette holds until a new one is ready.

### 9.6 How a swap animates

Writing the value a theme reads, a portal change, a new wallpaper,
`strand set` and saving a theme file all take the same path:

1. Dependent tokens re-resolve.
2. Only the palette roots spring, in OKLab; every derived token is
   re-evaluated from them each frame, so it stays exact mid-animation.
3. **Contrast guard.** Text lightness is solved to keep the declared
   text/background pairs at 3:1 or better throughout. Where a light↔dark
   swap makes that impossible, the surface snapshots its old frame once
   and crossfades.
4. What cannot interpolate snaps (section 6.6).

## 10. Identity, state and reload

Saving a file is a state change, not a restart. A reload reconciles the
new program with the running one.

### 10.1 What each edit does

| Edit | What happens | State kept? |
| --- | --- | --- |
| Token value | Token table swapped; colours spring | Yes |
| Prop or binding | Patched in place; animates from its current value | Yes |
| Node added or removed | `enter` / `exit` play; siblings glide | Yes, elsewhere |
| `state` default | Adopted only if the value was never changed | Yes, if you changed it |
| `state` name or type | That one cell resets, with a warning | No, that cell only |
| Handler code | Restarted; an in-flight `await` is cancelled and reported | Yes |
| Timer duration | Remaining time rescaled | Yes |
| Surface layer, namespace or kind | Only that surface is recreated | Yes |
| Custom service declaration | Only that service restarts; built-ins never do | Yes |
| Anything inside `lock` | Deferred until unlock | Yes |

- A handler counts as changed when its code or anything it reaches
  (the `fn`s and `let`s it calls or reads) changed; an unchanged handler
  keeps its in-flight work.
- A rescaled timer keeps the fraction it has counted and finishes at the
  new duration; an `after` that already ran stays done.
- A surface's state is keyed by its place in the program, not its name,
  so a renamed surface keeps it. Turning a `bar` into a single surface
  keeps its state when it had one instance, and resets it with a warning
  when it had several.

### 10.2 Identity

- A node keeps its identity while its source text maps to it, so editing
  a node's own props never resets it, and wrapping a node in a container
  keeps it. Next, `key` or `id` decides, then position among siblings of
  the same kind. A changed kind is a new node. Real ambiguity resets with
  a warning; Strand never guesses.
- Nodes moved into a different component (by hand, or by the LSP's
  "extract component") are new nodes: their state resets.
- State lives on components, surfaces and list items, never on leaf
  elements (section 5.3), so editing a node cannot take a popup's state
  with it.
- A `bar`'s per-monitor state is keyed by the monitor (make, model and
  description) and survives a reload, and an unplug of up to 30 s.

### 10.3 State defaults and persistence

- A state cell takes a new default only if it still holds the old one.
  Otherwise it keeps its value and the reload overlay says so:
  `launcher.query: kept "fir" (default changed) [reset]`.
- An adopted default, and any other change a reload makes to a live
  cell, is a **reload write**: `on change` takes it as its baseline and
  does not fire.
- **`persist`** stores the value with a hash of its default, under
  `$XDG_STATE_HOME/strand/persist`. At start, a stored value whose
  default hash matches is used; when the default changed, an unchanged
  stored value adopts the new default and a changed one is kept and
  reported once. A corrupt store gives the default and a warning.

### 10.4 Escape hatches

- **`@reset`** on a `state` declaration resets that cell to its default
  (and removes its persisted value) when a reload commits it; the other
  cells are untouched. **(unverified)**: whether a later reload that
  keeps the attribute resets the cell again.
- **Reset subtree** (the inspector, IPC `reset{node}`) resets the state
  under one node, as `strand reload --hard` does for the whole shell.
  Settings are untouched.
- **`strand reload --hard`** drops non-persisted state and recreates
  every surface.

### 10.5 The commit

1. **Coalesce.** A reload waits 15 ms after the last completed write, so
   "save all" is one batch (50 ms when the latest event removed a
   watched file, so delete-then-create is one edit; never more than
   500 ms in all).
2. **Skip no-ops.** A file whose content is unchanged stops here,
   including Strand's own writes.
3. **Check.** The changed modules are parsed and the program is
   type-checked off the rendering path; the shell keeps running.
4. **Commit atomically.** The largest changed set that type-checks with
   everything that references it is committed in one tick, with no
   blank frame; the rest is held back with its diagnostics.
5. **Keep the last good tree.** On error the running shell stays as it
   was. The last good sources are cached, so a config broken at boot
   runs its last good version.

## 11. Settings files

`state prefs from "prefs.toml" { accent: color = #7aa2f7; compact: bool =
false }` declares typed, two-way settings stored in a TOML file that
people can edit by hand.

- A relative path is resolved against the config directory; `~/…` is
  in the home directory.
- Each field is `name: type = default`. Fields are read as
  `prefs.accent`; the record itself is not assignable, only its fields.
- **Each field is checked on its own.** A bad value keeps that field's
  last good value with a diagnostic; the other fields still apply. A
  TOML syntax error keeps every last good value. A deleted key springs
  back to its default. The first write creates a file that does not
  exist yet, and its missing directories. **(unverified)**: a file that
  does not exist yet gives every field its default.
- Edits to the file apply live, as per-field writes.
- **Writes** (`<->`, handler assignments, `strand set prefs.compact
  true`) are saved after 250 ms of quiet and keep the file's comments,
  spacing and order. They follow
  symbolic links and replace the file through a temporary file and a
  rename. A read-only target (such as a file in `/nix/store`) gets the
  write in an overlay under `$XDG_STATE_HOME/strand` instead, with a
  notice.
- Who wins between the overlay, the file and the default: section 8.8.

## 12. Errors and faults

- **Load errors** (sections 2 and 10.5) never stop a running shell. A
  load error that survives 250 ms of quiet opens a dismissible overlay
  listing every diagnostic with its labels and fixes; clicking one opens
  the file in `$EDITOR`. A save fixed within those 250 ms (format on
  save, delete then create) never opens it.
- **Runtime faults** freeze only their own component, outlined in red,
  until a reload fixes it; the rest of the shell runs on. A fault inside
  the `lock` shows the built-in password field (section 5.1).
- **Service failures** reach the program as values (an action's error,
  an `Async`'s `.error`) and as service diagnostics; they never stop the
  shell.

## 13. The command line and IPC

- `strand run [dir]` runs a config; `strand check [dir | file]` checks
  it without running it; `strand fmt [--check] [paths]` formats files.
- A running shell answers commands over a Unix socket
  (`$STRAND_SOCKET`, else `$XDG_RUNTIME_DIR/strand-<display>.sock`) and
  over D-Bus:
  - `strand get path` reads an exported value, a settings field or a
    token (`$accent`); service fields are not read;
  - `strand set path value` writes an exported `state` or a field of one
    (an ordinary write), a settings field, a token (a runtime overlay;
    section 8.8), or an `rw` service field. The value is text read by
    the target's type: an enum variant by name, `true`/`false`, a number
    with its unit, `#rrggbb`, `null` for an optional. For a service
    field, a signed number or percentage (`+5%`) is a step from the
    current value, never below 0;
  - `strand toggle path` flips an exported `bool` state;
  - `strand call target args…` calls a service-level action;
  - `strand clear path` removes a runtime overlay;
  - `strand watch [--json]` streams reload events: files, edit class,
    kept and reset cells, timing and diagnostics;
  - `strand reload [--hard]` rescans now (section 10.4).
- Paths use the program's own names: `file.name` for exports
  (`launcher.open`); `file.settings.field` for a settings field, or
  `settings.field` when exactly one file declares settings with that
  name, exported or not (`prefs.compact`); `service.field` for a service
  field (`audio.sink.volume`); `$token` for a token.
- **The D-Bus name** is `io.github.jakeb_grant.Strand`, both the bus
  name and the interface name, at object path `/`, owned when
  `strand run` starts; a second running instance runs without D-Bus IPC.
  **The name may change before 1.0** (decisions.md m5-owner, Q12).
- `strand help` lists every command. Commands, their flags and their
  output formats are covered by the compatibility policy only where this
  section names them.

## 14. Compatibility

In 1.x:

- no syntax is removed, and no syntax changes meaning;
- builtin schema entries (elements, props, service fields, actions) are
  only added, never removed or changed in meaning.

So a program accepted in 1.x stays accepted with the same meaning; a
program rejected may become accepted when a rule is added. Diagnostic
codes and wording, performance targets, and CLI surface section 13 does
not name are outside this policy (decisions.md m5-docs).

Anything else waits for 2.0. After the freeze, any change to
grammar.md or spec.md needs a decisions.md paragraph citing this
section; typo fixes are exempt. The freeze is held by this process and
by the conformance tests (the fixture tests, the tree-sitter conformance
test and the guide's ladder test), not by a hash pin.
